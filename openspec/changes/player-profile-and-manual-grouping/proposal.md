# 提案：玩家角色创建与手动分组选择

## 摘要

在进入游戏前增加角色创建环节（选择用户名和预设卡通头像），并将原有服务端自动分组逻辑替换为玩家手动选组，三个固定组名为"太阳组"、"大树组"和"小花组"。

## 问题

当前游戏流程中，玩家进入大厅后由服务端自动分配组别，没有角色身份感，也无法自主决定与谁组队。对幼儿而言，缺乏角色归属感和自主选择感会降低参与意愿。

## 目标

- 玩家进入游戏后须完成角色创建：输入用户名 + 从预设卡通头像中选择一个。
- 角色创建完成后，进入分组选择界面，三组固定为"太阳组"、"大树组"和"小花组"。
- 每组最多4人；已满的组显示锁定状态，禁止加入。
- 选组确认后才能进入对应的 GroupRoom 开始游戏。
- 删除服务端原有的轮询自动分组逻辑，完全由玩家手动选择。

## 非目标

- 账号持久化（不存储用户名或头像到数据库）——本次仅会话内有效。
- 自定义头像上传——仅提供预设卡通头像。
- 组名可配置——三组名称在本阶段固定不变。

## 动机

赋予幼儿玩家角色身份（名字+形象）和自主选择组别的权利，可显著提升代入感和社交互动意愿，符合幼儿教育中"主体性培养"的理念。

## 成功标准

1. 玩家进入后必须完成角色创建才能继续，用户名为必填项，头像为必选项。
2. 分组界面实时显示三组当前人数；已满4人的组处于不可点击的灰显状态。
3. 玩家选组并确认后直接加入对应 GroupRoom，游戏体验与原有流程一致。
4. 服务端 LobbyRoom 不再自动分配 groupId，改为接受客户端发送的选组请求。
5. 玩家头像和用户名在 GroupRoom 内对同组其他玩家可见（显示在 PlayerAvatar 上）。
