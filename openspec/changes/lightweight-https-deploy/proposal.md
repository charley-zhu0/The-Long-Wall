# 提案：轻量化 HTTPS 一键部署优化

## 摘要

优化现有 Docker Compose 部署方案，使其能够在内存 < 2GB 的低配置机器上稳定运行，支持 HTTPS 协议（含自签名证书），并提供一键部署脚本，只需配置目标服务器 IP 地址即可完成全套部署。

## 问题

### 1. 现有方案内存占用过高

当前部署方案使用两个容器：
- `game-server`（Node.js + Colyseus）：约 300–500MB RSS
- `nginx`（nginx:alpine 镜像）：约 20MB

构建阶段（`npm install` + `npm run build`）在宿主机或 CI 上需要临时占用 1–1.5GB 内存；在 2GB 以下机器上，构建与运行同时进行会触发 OOM 或大量 swap，导致部署失败。

### 2. 仅支持 HTTP，无 HTTPS

现有 nginx.conf 只监听 80 端口，不支持 HTTPS。现代浏览器对 HTTP WebSocket (`ws://`) 和摄像头/麦克风权限有严格限制，部分平板浏览器（Safari、Chrome）会拒绝在非 HTTPS 页面建立 WebSocket 连接或阻止权限请求。对于无域名的局域网/内网部署场景，需要支持自签名证书。

### 3. 部署步骤复杂，缺乏自动化

当前部署需要：安装 Docker、安装 Docker Compose、手动 clone 仓库、手动构建、手动配置 nginx。没有统一的一键部署入口，对非技术教师/运维人员不友好。

## 目标

- 确保完整运行时内存占用 < 800MB（为系统和其他进程保留 1.2GB 余量，总机器内存 < 2GB）。
- 支持 HTTPS 443 端口，同时保留 HTTP 80 端口（重定向至 HTTPS）。
- 支持自签名证书自动生成（openssl），无需手动配置证书。
- 提供 `deploy.sh` 一键部署脚本：用户只需修改一个 IP 变量即可完成完整部署。
- 构建过程与运行过程分离，避免在低内存机器上构建时 OOM。

## 非目标

- 不支持 Let's Encrypt 或 ACME 自动证书（需要公网域名，不适用内网场景）。
- 不修改游戏服务端（Colyseus）或客户端代码。
- 不提供负载均衡或多节点部署（单机即可满足 12 人同时在线需求）。
- 不修改开发环境配置（`npm run dev` 保持不变）。

## 动机

游戏实际部署场景为学校局域网内网服务器，通常为低配 Linux 机器（2GB RAM，2 核 CPU）。教师需要独立完成部署，不具备 Docker/nginx 专业知识。当前方案在此环境下部署失败率高，且缺乏 HTTPS 支持，导致平板浏览器出现兼容性问题。

## 成功标准

1. 在 2GB RAM 机器上，`docker compose up` 成功启动，运行时内存占用 < 800MB。
2. 浏览器访问 `https://<IP>` 可正常打开游戏（接受自签名证书警告后）。
3. WebSocket 连接通过 `wss://` 协议建立成功。
4. 执行 `deploy.sh` 后（仅修改 IP 变量），完整部署在 10 分钟内完成，无需任何额外手动操作。
5. HTTP 80 端口访问自动重定向至 HTTPS 443。
