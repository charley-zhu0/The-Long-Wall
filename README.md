# 长城协作建造游戏 (The Long Wall)

面向幼儿的多人在线3D像素（Voxel）协作游戏，玩家分组合作搭建与修复长城，培养空间想象力、动手能力和团队协作精神。

## 功能特色

- **多人协作**：最多12名玩家同时在线，分成3组（每组4人）各自完成长城修复任务
- **教师模式**：教师以上帝视角巡视各组，可高亮提示错误位置并发送鼓励标识
- **蓝图引导**：半透明虚影指引玩家在正确位置放置方块
- **实时同步**：基于 Colyseus 的权威服务端状态同步，延迟 ≤200ms
- **稳固性检测**：销毁方块时自动检测悬空结构并发出警告
- **多端支持**：PC（鼠标键盘）和平板（触屏）均可操作

## 快速开始（开发模式）

### 前置要求

- Node.js 18+
- npm 9+

### 安装依赖

```bash
npm install
```

### 启动开发服务器

```bash
npm run dev
```

同时启动：
- 客户端 Vite 开发服务器：`http://localhost:3000`
- 服务端 Colyseus：`ws://localhost:2567`

> Vite 已配置 `/colyseus` 路径的 WebSocket 代理，无需额外配置。

## 生产部署

### 方式一：Docker Compose（推荐）

```bash
docker compose up --build
```

启动后：
- 游戏入口：`http://localhost`（Nginx 端口 80）
- Colyseus 管理面板：`http://localhost:2567/colyseus`

服务说明：
- `game-server`：Node.js 游戏服务，端口 2567
- `nginx`：反向代理 + 静态文件服务，端口 80，`/colyseus/` 路径代理至游戏服务

### 方式二：手动构建

```bash
# 构建前后端
npm run build

# 启动服务端
node server/dist/index.js
```

环境变量：

| 变量 | 默认值 | 说明 |
|------|--------|------|
| `PORT` | `2567` | 服务端监听端口 |
| `NODE_ENV` | `development` | 运行环境 |
| `VITE_SERVER_URL` | `ws://localhost:2567` | 客户端连接的服务端 WebSocket 地址 |

## 游戏流程与角色说明

### 标准开局流程

```
[教师] 打开 /teacher 进入教师端
        ↓
[学生] 打开游戏页面 → 创建角色 → 选择小组 → 等待游戏开始
        ↓
[教师] 确认各组人数就绪 → 点击「开始游戏」
        ↓
[学生] 自动进入所选小组房间，看到预填长城 → 看完教程 → 开始建造
```

> **注意**：学生在选好小组后会看到「等待老师开始游戏…」的提示界面，此时需要等教师点击「开始游戏」才能进入游戏。反之，若教师先开始游戏，后来的学生选好组后会直接进入。

---

### 学生玩家

1. 打开 `http://localhost`（或服务器地址）
2. **创建角色**：输入昵称，选择头像
3. **选择小组**：从太阳组（1）、大树组（2）、小花组（3）中选择一个，每组限 4 人
4. 等待老师开始游戏（若游戏已开始则直接进入）
5. 阅读新手引导后开始游戏
6. 按照半透明蓝图虚影，将缺失的方块填补完整，全组完成后触发通关

### 教师

#### 进入教师端

打开 `http://localhost/teacher`（或 `http://服务器地址/teacher`）。教师端会自动以观察者身份加入全部三个小组房间，可飞行巡视。

#### 开始游戏

教师端界面包含「开始游戏」按钮，点击后服务端将：

1. 读取 `server/maps/section-1.json` 蓝图数据
2. 为三个小组各自创建独立的游戏房间
3. 将蓝图随机移除 30% 方块后预填入各组场景
4. 广播 `GAME_STARTED` 消息，已在等待的学生自动进入所属房间

> 建议等所有学生都选好小组后再点击「开始游戏」。

#### 巡视与互动

| 功能 | 操作说明 |
|------|----------|
| 飞行视角 | 教师端默认飞行相机，可自由移动俯视各组场景 |
| 高亮提示 | 在教师 HUD 中选择小组并输入坐标，点击「高亮」，该位置会在学生端显示高亮标记 |
| 发送鼓励 | 选择小组后点击 ⭐ 星星 / ❤️ 爱心 / 👍 点赞，对应组的学生屏幕上会出现鼓励动画 |

## 内置长城蓝图

### 蓝图工作原理

游戏启动后，服务端从 `server/maps/section-1.json` 读取蓝图数据，随机移除其中约 30% 的方块作为「残缺」部分，其余 70% 预先放置在场景中。玩家的目标是根据半透明虚影（BlueprintOverlay）将缺失的方块填补完整，触发 `SECTION_COMPLETE` 事件。

### 地图文件格式

蓝图文件位于 `server/maps/`，格式如下：

```json
{
  "name": "great-wall-section-1",
  "size": { "x": 20, "y": 8, "z": 6 },
  "blocks": [
    { "x": 0, "y": 0, "z": 0, "type": 1 },
    { "x": 0, "y": 4, "z": 0, "type": 2 },
    { "x": 0, "y": 5, "z": 0, "type": 3 }
  ]
}
```

| 字段 | 说明 |
|------|------|
| `name` | 地图名称（仅用于标识） |
| `size` | 地图尺寸参考（不强制限制，服务端以网格边界为准） |
| `blocks` | 方块数组，每个方块包含坐标 `x/y/z` 和类型 `type` |

方块类型：

| `type` | 名称 | 造型 |
|--------|------|------|
| `1` | 灰砖 | 标准立方体 (1×1×1) |
| `2` | 垛口 | U 形城齿（顶部中间有缺口） |
| `3` | 烽火台 | 阶梯塔（上层比下层窄） |

坐标系约束（超出范围的方块会被服务端静默忽略）：
- `x, z ∈ [-32, 32]`
- `y ∈ [0, 32]`

### 创建自定义长城地图

1. 在 `server/maps/` 目录下新建 JSON 文件，例如 `section-2.json`，按照上述格式编写方块数据。

2. 修改 `server/src/rooms/LobbyRoom.ts` 第 87 行，将蓝图路径改为新文件：

   ```ts
   const blueprintPath = path.resolve(__dirname, '../../maps/section-2.json')
   ```

3. 重启服务端，教师点击「开始游戏」后三个小组房间将使用新蓝图。

### 典型长城结构参考

以下是一段 `section-1.json` 所呈现的典型长城剖面（俯视 x-z 平面，y 为高度）：

```
y=0~3  灰砖（type=1）构成城墙主体，宽 2（z=0,1），长 20（x=0~19）
y=4    灰砖铺设城墙走道（行走平台）
y=5    垛口（type=2）间隔排布于 z=0 侧，形成城齿
y=6~7  烽火台（type=3）在 x=0 和 x=19 两端各一座
```
